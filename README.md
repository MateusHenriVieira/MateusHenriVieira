## How I work

I build software that has to survive real-world conditions — inconsistent internet, non-technical users, strict municipal budgets, sensitive data. This shapes how I approach every project:

- **Offline-first by default.** Network is a bonus, not a requirement.
- **Simple over clever.** Code that the next developer can read in six months.
- **Ship small, iterate fast.** A working MVP beats a perfect plan.
- **Document as I go.** READMEs, commits, and decisions logs are part of the deliverable.
